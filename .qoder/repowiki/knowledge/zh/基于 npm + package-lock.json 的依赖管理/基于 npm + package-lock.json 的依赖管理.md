## 1. 使用的系统与工具

本项目采用 **npm** 作为包管理器，通过根目录的 `package.json` 声明运行时与开发时依赖，使用同目录下的 `package-lock.json` 作为锁定文件（lockfile）以保证安装结果可重现。构建与运行脚本由 Next.js 官方 CLI 提供：`dev`、`build`、`start`、`lint`。

- 运行时核心框架：`next ^16.3.0`、`react 19.2.8`、`react-dom 19.2.8`
- UI 组件体系：基于 Radix UI（`@radix-ui/*`）、Tailwind CSS v4（`tailwindcss ^4.3.3`、`@tailwindcss/postcss ^4.3.3`）、`class-variance-authority`、`clsx`、`tailwind-merge`、`tw-animate-css`
- 动画：`motion`（Framer Motion）
- 表单与校验：`react-hook-form` + `@hookform/resolvers` + `zod ^4.4.3`
- 状态管理：`zustand ^5.0.14`
- 博客渲染：`gray-matter` + `remark` / `remark-gfm` / `remark-html`
- 图标：`lucide-react`、`react-icons`
- 分析/主题：`@vercel/analytics`、`next-themes`、`@next/third-parties`
- 开发工具链：TypeScript `^6.0.3`、ESLint `^10.8.1`（含 `eslint-config-next`）、Prettier `^3.9.6`（含 `prettier-plugin-organize-imports`）

## 2. 关键文件

- `package.json`：唯一依赖声明入口，包含 `dependencies`、`devDependencies`、`scripts`、`overrides`、`allowScripts`。
- `package-lock.json`：npm 生成的锁定文件，用于固定所有依赖及其传递依赖的版本，确保跨环境一致安装。
- `.gitignore`：排除 `/node_modules`、`.pnp*`、`.next/`、`*.tsbuildinfo`、`next-env.d.ts` 等生成产物；未将 `package-lock.json` 加入忽略，说明其应被提交到版本库。
- `tsconfig.json`：配置 TypeScript 编译目标为 ES2017，模块解析策略为 `bundler`，并通过 `paths` 映射 `@/*` 指向项目根目录，实现路径别名导入。
- `next.config.js`：仅配置 API 路由 CORS headers，不引入额外第三方运行时依赖。
- `postcss.config.js`、`components.json`：配合 Tailwind v4 与 shadcn/ui 风格的组件注册。

## 3. 架构与约定

- **单一来源声明**：所有第三方依赖集中在 `package.json` 中按功能分组（UI、动画、表单、博客、工具、开发工具），无分散的 `yarn.lock`、`pnpm-lock.yaml` 或 `go.mod`。
- **版本范围策略**：运行时依赖普遍使用 `^` 语义化版本范围（如 `next ^16.3.0`、`react 19.2.8` 精确主版本），在保持兼容性的同时允许小版本升级；通过 `package-lock.json` 锁定实际安装版本。
- **依赖覆盖（overrides）**：在 `package.json` 的 `overrides` 字段中将多个 ESLint 插件（`eslint-plugin-react`、`eslint-plugin-import`、`eslint-plugin-jsx-a11y`）强制绑定到项目自身的 `eslint` 版本，避免嵌套 ESLint 实例冲突。
- **危险脚本白名单**：通过 `allowScripts.unrs-resolver@1.12.2: true` 显式允许该包的预构建脚本执行，体现对第三方脚本的安全管控意识。
- **路径别名**：通过 `tsconfig.json` 的 `paths` 将 `@/*` 映射到项目根目录，统一内部模块导入风格，减少相对路径依赖耦合。
- **无 vendoring**：没有 `vendor/`、`lib/vendor/` 等内联第三方源码目录，也不存在私有 npm registry 配置；所有依赖均从默认 npm registry 拉取。

## 4. 约定与约束

- **包管理器锁定**：项目使用 npm 并依赖 `package-lock.json` 保证安装一致性；`.gitignore` 未忽略 lockfile，表明应随代码一同提交。
- **禁止未声明依赖**：所有运行时与开发时依赖均在 `package.json` 中显式声明，未发现 `require()` 或 `import` 来自未声明包的行为（基于当前扫描范围）。
- **严格类型检查**：`tsconfig.json` 启用 `strict: true`、`skipLibCheck: true`、`isolatedModules: true`，要求依赖具备类型定义或通过 `@types/*` 提供。
- **构建产物隔离**：`node_modules`、`.next`、`out`、`build` 等目录均被 `.gitignore` 排除，依赖与构建产物不参与版本控制。
- **Next.js 生态对齐**：`eslint-config-next`、`@next/eslint-plugin-next`、`next` 三者版本保持一致（均为 `16.3.0`），遵循 Next.js 官方推荐的版本搭配。
- **无私有仓库/代理配置**：未发现 `.npmrc`、`.yarnrc`、`pnpm-workspace.yaml` 等自定义 registry 配置，依赖来源为标准 npm registry。
- **脚本安全**：通过 `allowScripts` 白名单机制限制第三方包预构建脚本的执行，属于 npm 安全策略的一部分。
